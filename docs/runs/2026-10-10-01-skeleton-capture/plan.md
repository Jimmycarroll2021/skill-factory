Assumptions: `skillz new <source>` treats `source` as a file path when it names an existing `.txt`, `.yaml`/`.yml` or `.json` file and as paragraph text otherwise; `--name` overrides the derived name; output goes under `<cwd>/skills/<name>/` (an `--out` root option is allowed); the structured spec is written to `skills/<name>/.factory/spec.json` so the skill root holds only `SKILL.md`, `scripts/`, `references/`, `assets/` and the factory's own `.factory/` (as REQ-002 requires later). The CLI uses argparse (stdlib). The build backend is hatchling unless the worker finds it does not work with `uv build`. Tests in `tests/` named `test_*.py` are the only pytest tests; `tests/controller.py`, `tests/hardening.py`, `tests/readiness.py` and `tests/*.sh` are harness files that pytest must not collect and ruff must not lint.

Order: tasks 1 and 2 run in parallel. Task 3 depends on both and starts after they are merged. Mission 01 may exceed 10 changed files (PRD "Delivery slicing"): the extra files are short boilerplate, fixtures and `uv.lock`.

1. slug: `pkg-skeleton`
   - goal: Make the repository an installable, buildable uv package `skill_factory` (Python 3.12, src layout, no runtime dependencies, dev dependencies pytest and ruff only, console script `skillz = "skill_factory.cli:main"`) with a committed `uv.lock`, pytest collection limited to `tests/test_*.py`, ruff limited to `src` and `tests/test_*.py` (harness files in `tests/` excluded), an MIT `LICENSE`, Python entries added to `.gitignore` (`.venv/`, `dist/`, `__pycache__/`, `*.egg-info/`, `.pytest_cache/`, `.ruff_cache/`, keeping the existing lines), and `.github/workflows/ci.yml` running `uv run ruff check src tests` and `uv run pytest -q` on a matrix of `ubuntu-latest` and `windows-latest` (a test workflow only, no deploy or publish step).
   - owns: `pyproject.toml`, `uv.lock`, `src/skill_factory/__init__.py`, `LICENSE`, `.gitignore`, `.github/workflows/ci.yml`
   - needs_web: no
   - done when: criterion 4 (`uv build` exits 0). This task also makes criteria 5 (`LICENSE` contains "MIT License") and 6 (`windows-latest` in ci.yml) pass, and `uv run ruff check src tests` must exit 0 on its own merge.
   - depends on: nothing.

2. slug: `capture-spec`
   - goal: Turn a paragraph (text or `.txt` file) or a small YAML or JSON spec file into a deterministic structured skill spec (name in kebab-case at most 64 chars, derived from the first meaningful words unless overridden; description from the first sentences, non-empty, at most 1024 chars; triggers, non-triggers, expected behaviours; optional license, allowed-tools, metadata; which of `scripts`/`references`/`assets` are requested), using an in-package YAML subset reader/writer (scalars, lists, one level of mappings; no PyYAML) that round-trips the spec and can emit SKILL.md frontmatter; invalid specs (bad name, empty or overlong description, unknown resource dirs) raise a clear error.
   - owns: `src/skill_factory/yamlish.py`, `src/skill_factory/capture.py`, `tests/test_capture.py`, `tests/fixtures/paragraph.txt`, `tests/fixtures/spec.yaml`, `tests/fixtures/spec.json`
   - fixtures contract (task 3 relies on it): `paragraph.txt` is a real multi-sentence paragraph that requests no resource directories; `spec.yaml` requests `references` only; `spec.json` requests `scripts` and `assets`. Each fixture yields a different skill name.
   - needs_web: no
   - done when: `uv run pytest -q tests/test_capture.py` exits 0 (checked on the merged branch, after task 1 supplies `pyproject.toml`).
   - depends on: nothing for implementation (the worker may run tests with `PYTHONPATH=src` before task 1 merges); its check needs task 1 merged.

3. slug: `generate-cli`
   - goal: Wire `skillz new` end to end: a `skillz` argparse CLI (`skillz --help`, `skillz new --help`, `python -m skill_factory`) whose `new` subcommand captures a paragraph or spec via task 2's capture module, writes `skills/<name>/.factory/spec.json`, and generates `skills/<name>/SKILL.md` with compliant YAML frontmatter (`name` equal to the directory name, kebab-case, at most 64 chars; non-empty `description` at most 1024 chars; `license`, `allowed-tools`, `metadata` only when given) and a short body, creating `scripts/`, `references/` or `assets/` only when the spec requests them; UTF-8 with LF line endings, pathlib only; it refuses to overwrite an existing skill unless `--force` is passed. Tests run `skillz new` (via `cli.main([...])` or a subprocess) in `tmp_path` on the paragraph, YAML and JSON fixtures and assert on the parsed frontmatter and on which resource directories exist.
   - owns: `src/skill_factory/generate.py`, `src/skill_factory/cli.py`, `src/skill_factory/__main__.py`, `tests/test_generate.py`
   - needs_web: no
   - done when: criterion 1 (`uv run pytest -q tests/test_capture.py tests/test_generate.py` exits 0). Criteria 0, 2, 3 and 7 must also pass after this merge.
   - depends on: tasks 1 and 2 (needs `pyproject.toml`, the console script target, `capture.py`, `yamlish.py` and the fixtures).
