# Idea

skill-factory is a skills factory: a meta-skill for Claude Code and Codex that turns a one-paragraph description of a capability into a complete, tested, versioned Agent Skill, instead of writing skills by hand one at a time. Today a developer who wants Claude or Codex to do a new kind of job hand-writes a SKILL.md, guesses at the trigger description, never tests it against a baseline, and has no record of which version worked. The factory runs a continuous pipeline from a single `skillz` command: capture the capability as a structured skill specification; generate a portable skill (SKILL.md plus `scripts/`, `references/` and `assets/` only when justified); render thin Claude-specific and Codex-specific install variants from that one canonical source; validate structure and security statically; generate positive and negative trigger tests and behavioural evaluation cases; run the candidate skill against a no-skill baseline, grade the outputs, and propose improvements to weak areas; run regression tests; hold the result as a versioned package until a human approves it; then install it into the chosen platform directory and record it in a registry of proven skills. Every released version stays available for rollback. The factory can improve itself the same way, as a challenger: a candidate factory version is produced, run through the same meta-evaluations and regression comparison as the stable one, and only replaces it after human approval. The evaluation engine, the regression suite, the version history and the accumulated registry of proven skills are the valuable part, not the initial prompt that drafts the SKILL.md.

## Constraints

- Stack: Python 3.12 managed with uv (`pyproject.toml`, `pytest`, `ruff`, `uv build`). No runtime dependencies beyond the standard library; pytest and ruff are the only dev dependencies.
- Repository name is skill-factory; the package is `skill_factory`; the CLI command is `skillz`.
- Every pipeline stage must work offline and deterministically with no model calls, so the test suite needs no network, API key or logged-in CLI. Model-backed evaluation runs shell out to the `claude` CLI (and `codex` when present) only when the user asks for them and the executable is on PATH; otherwise the stage records "skipped: no runner" and the pipeline still completes.
- Skills follow the open Agent Skills specification: a `SKILL.md` with YAML frontmatter where `name` is kebab-case, matches the directory name and is at most 64 characters, `description` is non-empty and at most 1024 characters, and optional `license`, `allowed-tools` and `metadata` fields; progressive disclosure with the body kept short and detail moved to `references/`; supporting files only in `scripts/`, `references/` and `assets/`.
- Claude install target is `.claude/skills/<name>/` in a project or `~/.claude/skills/<name>/` for the user; Codex install target is `.agents/skills/<name>/` plus an optional `agents/openai.yaml` describing the skill. Both are rendered from the one canonical skill source; the canonical source is never edited per platform.
- The factory never runs a generated skill's scripts during validation; validation is static (frontmatter, names, paths, size limits, forbidden patterns such as secrets, network calls or destructive shell in scripts). It never calls `git push`, never writes outside the working project and the chosen install directory, and never installs or promotes anything without an explicit human approval command.
- Public-ready from day one: MIT licence, a README with a quickstart and the pipeline diagram, CONTRIBUTING.md, CHANGELOG.md, a GitHub Actions workflow that runs ruff and pytest on Linux and Windows, a `.gitignore`, and `uv build` producing a wheel.
- Input: a paragraph of text, or a small YAML or JSON spec file. Output: a skill directory under `skills/<name>/`, machine-readable JSON reports for every stage under `skills/<name>/.factory/`, and Markdown summaries a human can read before approving.
